# Grill Me（深度設計訪談）

對使用者的計畫或設計進行全方位、深入且不留死角的訪談，直到雙方達成完全共識，並將結果持久化記錄至專案規格檔中。

## 執行原則

1. **先查閱現有專案與規格（Explore Before Asking）**：
   * 開始提問前，先檢查根目錄是否已有 `SPEC.md`、`DESIGN.md` 或現有程式碼。能從專案檔案得知的答案，請自行查閱，不要重複詢問使用者。
2. **走訪決策樹（Walk the Design Tree）**：
   * 沿著設計決策樹的每個分支逐步推進，逐一釐清各個決策之間的相依性。
3. **一次詢問一個問題（One Question at a Time）**：
   * 每次只提出一個核心問題（若工具支援，優先使用 `ask_question` 選擇題互動），避免一次拋出大量問題造成負擔。
4. **提供推薦答案（Provide Recommended Answer）**：
   * 針對每個提出的問題，附上你的推薦選項（標註 `(Recommended)`）與簡短理由，協助使用者快速決策。
5. **達成共識前不寫程式（No Code Until Consensus）**：
   * 在所有關鍵設計分支與邊界條件都釐清並獲得使用者確認之前，不要直接開始撰寫實作程式碼。
6. **持久化寫入 `SPEC.md` 與 `DESIGN.md`（Persist Decisions）**：
   * 當訪談達成共識（或使用者表示拷問結束）時，**主動將討論定案的「功能需求與邊界條件」寫入/更新至根目錄的 `SPEC.md`，並將「系統架構與技術選型決策」寫入/更新至根目錄的 `DESIGN.md`**，以確保跨視窗與跨模型記憶不流失。
